# AI_Agent_Artik

Персональный AI-агент на Node.js. Один и тот же агент работает как консольный ассистент, как Telegram-бот и как веб-интерфейс в браузере, хранит память по чатам, переключает роли, вызывает инструменты и анализирует результаты через LLM.

## Что умеет агент

- Отвечает на обычные вопросы через OpenRouter.
- Работает в нескольких ролях: обычный агент, JavaScript-наставник и архитектор.
- Запоминает пользовательские факты в долговременную память.
- Поддерживает хранение долговременной памяти в PostgreSQL через `DATABASE_URL`.
- Хранит краткосрочный контекст текущего диалога.
- Запоминает проекты — название, стек, задачи и статус — и позволяет вести их из чата.
- Выполняет простые команды: время, калькулятор, UUID, случайное число, Base64.
- Получает погоду через `wttr.in`.
- Ищет информацию через Tavily.
- Ищет видео на YouTube через YouTube Data API.
- Читает веб-страницы по URL и отдает текст страницы в анализатор.
- Получает новости через Google News RSS.
- Анализирует кодовую базу проекта через `Codebase Analyzer`.
- Генерирует картинки по текстовому описанию через `/draw`.
- Работает с Excel/CSV: поиск, аналитика, заказ поставщику и замовлення Т1, перенос товара между магазинами по условиям, развозка неликвида, документы перемещения, отчёт «непроданное», правка ячеек и листов книги.
- Работает в Telegram, включая текстовые сообщения, voice и audio.
- В Telegram принимает Excel/CSV-файлы и отправляет готовые `.xlsx`-отчёты документом.
- Показывает Telegram-кнопки для переключения агентов, команд и рисования.
- Делит длинные ответы для Telegram на части.
- Даёт простой веб-интерфейс в браузере: чат, кнопки быстрых действий, загрузка Excel/CSV файлов и скачивание готовых отчётов и картинок.
- Читает, создаёт и показывает структуру файлов проекта по запросу (`/write`, «прочитай файл …», «структура проекта»).
- Поднимает HTTP-сервер (переменная `PORT`) — он же веб-интерфейс, он же health-check при деплое на Render.

## Быстрый старт

1. Установи зависимости:

```bash
npm install
```

2. Создай `.env` в корне проекта.

Минимальный вариант для обычного AI-чата:

```env
OPENROUTER_API_KEY=твой_ключ_openrouter
MODEL_DEFAULT=openai/gpt-4o-mini
```

Опционально подключи PostgreSQL на Neon для долговременной памяти:

```env
DATABASE_URL=postgresql://user:password@ep-example.us-east-1.aws.neon.tech/neondb?sslmode=require&channel_binding=require
DATABASE_SSL=require
```

Для локального PostgreSQL без SSL можно использовать обычную строку подключения и отключить SSL:

```env
DATABASE_URL=postgresql://user:password@localhost:5432/ai_agent_artik
DATABASE_SSL=disable
```

3. Запусти CLI-режим:

```bash
npm start
```

4. Открой веб-интерфейс — он поднимается автоматически вместе с CLI или Telegram-ботом:

```text
http://localhost:10000
```

(порт задаётся переменной `PORT`, по умолчанию `10000`; см. раздел [«Веб-интерфейс»](#веб-интерфейс)).

5. Запусти Telegram-бота:

```bash
npm run telegram
```

6. Для 24/7-запуска Telegram-бота на сервере/VPS используй PM2-конфиг:

```bash
npx pm2 start ecosystem.config.cjs
```

7. Запусти тесты:

```bash
npm test
```

## Переменные окружения

| Переменная | Для чего нужна |
| --- | --- |
| `OPENROUTER_API_KEY` | Обязательна для обычных ответов AI, роутера инструментов, анализа результатов и распознавания аудио. |
| `MODEL_DEFAULT` | Основная модель для агента. |
| `OPENROUTER_MODEL` | Запасная основная модель, если `MODEL_DEFAULT` не задана. |
| `MODEL_CODER` | Модель для режима `coder`. Необязательно. |
| `MODEL_ARCHITECT` | Модель для режима `architect`. Необязательно. |
| `MODEL_ROUTER` | Зарезервирована под роутер инструментов. |
| `TELEGRAM_BOT_TOKEN` | Токен Telegram-бота от BotFather. Нужен для `npm run telegram`. |
| `PORT` | Порт встроенного HTTP-сервера: он же веб-интерфейс, он же health-check (например, при деплое на Render). По умолчанию `10000`. Обычно задаётся платформой автоматически. Понимает и «голое» число, и строку вида `0.0.0.0:10000` — число достаётся из конца строки. |
| `GUIDE_FILE_PATH` | Необязательный путь к тексту `/справка`. В Windows по умолчанию `D:/telegram excel/Справка — команды Telegram Excel.txt`, на Linux — `docs/telegram-excel-guide.txt` относительно каталога проекта. |
| `TAVILY_API_KEY` | Нужен для интернет-поиска через `/search` и похожие запросы. |
| `YOUTUBE_API_KEY` | Нужен для поиска YouTube-видео. |
| `OPENROUTER_STT_MODEL` | Модель распознавания речи. По умолчанию используется `openai/whisper-large-v3`. |
| `MODEL_STT` | Альтернативное имя переменной для STT-модели. |
| `OPENROUTER_STT_LANGUAGE` | Язык распознавания речи. |
| `STT_LANGUAGE` | Альтернативное имя переменной языка STT. |
| `IMAGE_MODEL` | Модель генерации и редактирования картинок через OpenRouter (нужна image-output модальность). По умолчанию `google/gemini-2.5-flash-image`. |
| `DATABASE_URL` | Строка подключения PostgreSQL. Если задана, долговременная память хранится в таблице `memories`. |
| `DATABASE_SSL` | SSL-режим PostgreSQL: `require`/`true` включает SSL, `disable`/`false` выключает. |
| `DATABASE_POOL_MAX` | Необязательный лимит пула `pg`. По умолчанию `1` для Neon pooler URL и `5` для прямого подключения. |
| `DATABASE_CONNECTION_TIMEOUT_MS` | Необязательный таймаут подключения к PostgreSQL. По умолчанию `10000`. |
| `DATABASE_IDLE_TIMEOUT_MS` | Необязательный таймаут простоя соединений пула. По умолчанию `30000`. |

## Роли агента

### `default`

Обычный персональный режим. Используется для общих вопросов, советов, объяснений, технических задач и повседневного общения.

### `coder`

Режим Senior JavaScript Developer и AI Engineer. Подходит для:

- JavaScript и Node.js;
- Telegram-ботов на Telegraf;
- AI-агентов;
- объяснения кода;
- готовых структур проектов.

Включить режим:

```text
/agent coder
```

Или разово:

```text
/coder объясни Promise.allSettled
```

### `architect`

Режим Solution Architect и AI Architect. Подходит для:

- проектирования систем;
- выбора стека;
- архитектурных ревью;
- планов разработки;
- масштабируемости и поддержки.

Включить режим:

```text
/agent architect
```

Или разово:

```text
/architect спроектируй AI-агента для Telegram
```

## Память

Долговременная память хранится в PostgreSQL, если в `.env` задана переменная `DATABASE_URL`. При старте агент создаёт таблицу `memories`, если её ещё нет. Если `DATABASE_URL` не задана, агент автоматически использует прежний файловый fallback `memory.json` в корне проекта.

Память разделяется по `chatId`, поэтому разные Telegram-чаты получают разные наборы записей.

Примеры:

```text
запомни я учу JavaScript
память
/history
/forget 1
/clear
```

Краткосрочная история хранится в объекте агента во время работы процесса. Она помогает модели помнить последние сообщения диалога. Лимит истории: последние 100 сообщений.

## Проекты

Агент запоминает проекты — по одному набору на чат, так же как и обычная память. У каждого проекта:

- **название** — например, «Telegram Shop Bot»;
- **стек** — свободный текст, например «Node.js, Telegraf, PostgreSQL»;
- **статус** — свободный текст, например «в разработке», по умолчанию «новый»;
- **задачи** — список с отметкой выполнено/не выполнено.

Как и с памятью, хранилище — таблица `projects` в PostgreSQL при заданной `DATABASE_URL`, иначе файл `projects.json` в корне проекта.

Примеры:

```text
создай проект Telegram Shop Bot
проект Telegram Shop Bot стек: Node.js, Telegraf, PostgreSQL
проект Telegram Shop Bot статус: в разработке
проект Telegram Shop Bot задача: подключить оплату
проект Telegram Shop Bot готово: подключить оплату
проект Telegram Shop Bot
/projects
удали проект Telegram Shop Bot
```

Создание проекта, который уже существует, не стирает его данные — агент покажет текущую карточку вместо того, чтобы завести пустую копию.

## Инструменты

### `time`

Возвращает локальное время через `new Date().toLocaleString()`.

### `calc`

Считает только простые математические выражения. Разрешены цифры, пробелы, скобки и операторы `+ - * / %`.

Пример:

```text
calc 2 + 2 * 3
```

### `weather`

Получает короткий прогноз через `wttr.in`.

Пример:

```text
/weather Луцк
```

### `search`

Ищет информацию через Tavily API. Нужен `TAVILY_API_KEY`.

Пример:

```text
/search что такое Model Context Protocol
```

### `webReader`

Открывает URL, удаляет `script` и `style`, достает текст из `body`, сжимает пробелы и возвращает первые 12000 символов.

Пример:

```text
прочитай сайт https://nodejs.org
```

### `youtube`

Ищет до 5 видео через YouTube Data API. Нужен `YOUTUBE_API_KEY`.

Пример:

```text
/youtube JavaScript event loop
```

### `news`

Берет новости из Google News RSS.

Пример:

```text
/news искусственный интеллект
```

### `draw`

Рисует картинку через image-модель OpenRouter (по умолчанию
`google/gemini-2.5-flash-image`) и сохраняет результат в `exports/`. В
Telegram бот отправляет файл как фото, в CLI печатает путь к нему.

Пример:

```text
/draw кот-программист в космосе
```

Готовую картинку можно отредактировать — команда запоминает последнюю
нарисованную в чате картинку и правит именно её:

```text
/editimage добавь на фото снег
измени картинку: сделай фон синим
```

Кроме того, в Telegram можно ответить (reply) текстом на любое фото в чате —
не обязательно нарисованное ботом — и бот отредактирует именно его.

### `codebase`

Собирает snapshot проекта и отправляет его в `resultAnalyzer`.

В snapshot попадают:

- ключевые файлы корня: `index.js`, `package.json`, `README.md`, `jsconfig.json`, `eslint.config.js`;
- директории `src` и `test`;
- файлы `.js`, `.ts`, `.tsx`, `.jsx`, `.mjs`, `.cjs`, `.json`, `.md`;
- дерево файлов;
- содержимое файлов с лимитами.

Исключаются:

- `node_modules`;
- `.git`;
- `dist`;
- `build`;
- `coverage`;
- `.next`;
- `tmp`.

Лимиты:

- до 8000 символов на файл;
- до 70000 символов всего.

Ответ Codebase Analyzer строится в формате:

1. Краткий вывод
2. Архитектура проекта
3. Сильные стороны
4. Проблемы
5. Что исправить первым
6. Рекомендации по файлам

### `fileReader`

Читает текстовый файл внутри проекта (путь проверяется, выход за каталог проекта
запрещён) и возвращает до 15000 символов содержимого.

Пример:

```text
прочитай файл src/agent.js
покажи файл README.md
```

### `projectTree`

Строит дерево файлов и папок проекта, пропуская `node_modules`, `.git`, `dist`,
`build` и `.env`.

Пример:

```text
структура проекта
дерево проекта
```

### `fileWriter`

Создаёт или перезаписывает файл проекта (тоже только внутри каталога проекта).
Команда обрабатывается напрямую, без LLM-роутера: путь и содержимое разделяются
символом `|`.

Пример:

```text
/write data/notes.txt | список покупок: молоко, хлеб
```

### `excel`

Работает с `.xlsx`, `.xls` и `.csv` внутри проекта: сам берёт последний присланный
файл или тот, что назван в запросе. Если одна и та же точка продаж встречается в
нескольких выгрузках, используется самая свежая — иначе её продажи посчитались бы
дважды.

- **Заказ поставщику / замовлення Т1** — рекомендация закупки по остаткам и прайсу
  или по отчёту движения/розничных продаж. Пороги по умолчанию (минимальная
  реализация, максимум дней запаса, число периодов, префиксы артикулов) заданы в
  [config.yaml](config.yaml) (`supply_settings`) и переопределяются прямо в
  запросе: `продаж%=20`, `days=90`, `периодов=3`, `prefixes=PJ,SO`.
- **Перенос по условию** — «перенеси с Т1 где реализация<20%» переносит товар
  между конкретными магазинами по условиям на реализацию, продажи, остаток или
  запас в днях.
- **Развезти по продажам** — «развези по продажам» переносит неликвид с точек,
  где товар не продаётся, на точки, где он продаётся.
- **Перемещение** — «перемещение» разбирает книгу с листами-маршрутами в одну
  плоскую таблицу; «шаблон перемещения с Т10» готовит пустую книгу по всей сети;
  можно и без Excel, прямо текстом: `Т10 на Т1: SO3206 12`.
- **Непроданное** — «что не продалось» / «неликвид» собирает из нескольких файлов
  товары без розничных и оптовых продаж за период.
- **Фильтр, поиск, аналитика** — «оставь только pjur» вырезает строки не по теме,
  поиск ищет строки по любым колонкам, аналитика считает сводку по книге.
- **Листы книги** — «покажи листы», «создай/удали/переименуй/скопируй лист»;
  исходный файл не меняется, результат — новая книга.
- **Правка ячеек** — «поменяй артикул A123 на B456 в data/ostatki.xlsx».

Настройки переноса (`cover_days`, `max_stock_days`, минимальная партия) и имена
точек продаж — тоже в `config.yaml` (`transfer_settings`, `points`).

Примеры:

```text
/excel заказ остатки=data/ostatki.xlsx прайс=data/price.xlsx
/excel замовлення data/t1.xlsx
Подготовь заказ поставщику.
/excel аналитика data/ostatki.xlsx
/excel поиск шампунь data/ostatki.xlsx
```

Если файлы уже загружены в Telegram или сохранены в памяти чата, можно писать
короче — просто `Подготовь заказ поставщику.`. Полную справку по всем сценариям
агент показывает по команде `/excel` без аргументов. Готовые файлы сохраняются в
папку `exports/`.

### `projects`

Ведёт проекты по чату: создание, карточка, список, стек, статус, задачи —
подробности и примеры в разделе [«Проекты»](#проекты) выше. Без аргументов
(`/project` без названия) показывает краткую справку по командам.

## Telegram-бот

Telegram-режим запускается командой:

```bash
npm run telegram
```

Нужна переменная:

```env
TELEGRAM_BOT_TOKEN=твой_telegram_bot_token
```

Бот умеет:

- отвечать на текстовые сообщения;
- хранить отдельную память для каждого чата;
- показывать `chatId` через `/whoami`;
- принимать voice и audio;
- скачивать аудио из Telegram;
- распознавать речь через OpenRouter STT;
- показывать кнопки `Агент: default`, `Агент: coder`, `Агент: architect`, `Нарисовать картинку` и `Команды`;
- отправлять сгенерированную или отредактированную картинку как фото-файл;
- отправлять длинные ответы частями до 3900 символов.

## Веб-интерфейс

Простой чат в браузере поверх того же агента — без установки Telegram и без
терминала. Поднимается автоматически вместе с CLI (`npm start`) или Telegram-ботом
(`npm run telegram`) на порту `PORT` (по умолчанию `10000`):

```text
http://localhost:10000
```

Что умеет:

- обычный чат текстом, с индикатором «печатает»;
- переключение роли агента (`Обычный` / `Программист` / `Архитектор`) кнопками
  в шапке — то же самое, что `/agent default|coder|architect`;
- кнопки быстрых действий для Excel — тот же набор, что в Telegram-меню
  (заказ поставщику, аналитика, непроданное, перенос по условию и так далее);
- загрузка Excel/CSV файла (кнопка 📎) — файл сохраняется и запоминается за
  текущей вкладкой браузера, как загрузка в Telegram;
- скачивание готовых отчётов (`.xlsx`) и сгенерированных картинок прямо из
  чата — ссылкой в ответе бота;
- у каждой вкладки браузера — своя сессия и своя память, как у отдельного
  Telegram-чата: сессия хранится в cookie и живёт 30 дней.

Технически: `src/web.js` поднимает Express-сервер (`GET /`, `POST /api/chat`,
`POST /api/upload`, `GET /files/:filename`), статика лежит в [public/](public/)
(`index.html`, `style.css`, `app.js`) — обычный HTML/CSS/JS без сборки и
фреймворков. Загрузка файла идёт через JSON (base64), а не `multipart/form-data`,
поэтому дополнительных зависимостей вроде `multer` не потребовалось.

⚠️ Аутентификации нет — как и у самого Telegram-бота, любой, кто откроет
адрес, может писать агенту и пользоваться его инструментами (включая чтение и
запись файлов проекта). Для публичного деплоя стоит закрыть доступ на уровне
платформы (пароль, VPN, allowlist по IP), если это важно.

## 24/7 запуск

Для работы при выключенном домашнем ПК нужен отдельный сервер. Подготовка и перенос на Linux VPS описаны в [deploy/README.md](deploy/README.md).

Альтернатива — деплой на Render (или любой PaaS с обязательным health-check
портом): `index.js` дополнительно поднимает веб-интерфейс на `PORT` (по умолчанию
`10000`) — `GET /` отвечает `200 OK` со страницей чата и держит деплой «живым»
независимо от режима запуска, а заодно даёт рабочий доступ к агенту по ссылке.
Сам бот при этом запускается тем же `npm run telegram` как процесс/сервис
платформы.

Для постоянной работы используй Telegram-режим вместе с Neon PostgreSQL:

```bash
npm run telegram
```

На сервере/VPS удобнее запускать через PM2, чтобы процесс автоматически поднимался после падения:

```bash
npx pm2 start ecosystem.config.cjs
npx pm2 save
```

Перед запуском проверь, что в `.env` заданы `TELEGRAM_BOT_TOKEN`, `OPENROUTER_API_KEY` и `DATABASE_URL`. Команда `/db` в Telegram показывает, подключена ли база и используется ли таблица `memories`.

## Как работает обработка сообщения

1. `Agent.process()` получает текст пользователя — из CLI, Telegram или веб-интерфейса, разницы для агента нет.
2. Сначала проверяются прямые команды: `/help`, `/tools`, память, калькулятор, погода, поиск и так далее.
3. Если команда относится к анализу проекта, запускается `tools.codebase`.
4. Если сообщение содержит URL и просьбу прочитать страницу, запускается `webReader`.
5. Если сообщение похоже на команду Excel (`shouldUseExcelTool`) или проектов (`shouldUseProjectManager`), запускается соответствующий инструмент напрямую, без LLM-роутера.
6. Если прямого правила нет, `routerAgent` пытается выбрать инструмент.
7. Если инструмент выбран, результат передается в `resultAnalyzer`.
8. Если инструмент не нужен, сообщение идет в обычный LLM-ответ через `askAi()`.

## Анализ результатов

Файл `src/resultAnalyzer.js` превращает сырой вывод инструментов в человеческий ответ.

Для `codebase` используется отдельный prompt Codebase Analyzer. Для остальных инструментов используется общий Ranker/Analyzer, который убирает мусор, выбирает главное и отвечает кратко на русском.

## Тесты

Тесты лежат в `test/agent.test.js`, `test/image-regressions.test.js` и
`test/review-regressions.test.js`. Сейчас покрыто:

- сохранение и чтение памяти;
- безопасный калькулятор и отклонение опасных выражений;
- наличие инструментов `/codebase` и `/draw` в реестре, генерация картинки без сети;
- переключение режимов агента;
- заказ поставщику и замовлення Т1 из файла, из памяти чата и из отчёта о движении;
- сужение заказа по категориям («только презервативы и лубриканты»);
- объединение строк одного артикула с разных точек в заказе поставщику
  (`combineSheetLines`) в одну строку с пересчитанным количеством;
- Excel-модуль: листы книги, документы перемещения, переносы по критериям,
  развозка неликвида, реестр торговых точек, фильтр по названию, отчёт «непроданное»;
- изоляция файлов Excel по `chatId` — чужие загрузки не подмешиваются;
- проекты: создание, повторное создание без потери данных, стек, статус,
  задачи, список, удаление, отказ ложно срабатывать на случайное упоминание
  слова «проект» в обычной фразе;
- регрессии: последняя загруженная книга при операциях с листами, поиск товара
  не путает служебные слова из подсказки с запросом.

Все тесты изолированы от боевых данных: каждый тест, которому нужна память или
проекты, заводит свой `chatId` и очищает его до и после — иначе `new Agent()`
без явного `chatId` попал бы в тот же чат `"default"`, которым, возможно,
пользуются по-настоящему.

Запуск:

```bash
npm test
```

## Ограничения

- Большая часть AI-функций требует `OPENROUTER_API_KEY`.
- Интернет-поиск требует `TAVILY_API_KEY`.
- YouTube-поиск требует `YOUTUBE_API_KEY`.
- Telegram-режим требует `TELEGRAM_BOT_TOKEN`.
- Если `DATABASE_URL` не задана, память и проекты хранятся локально в
  `memory.json` и `projects.json`.
- `Codebase Analyzer` анализирует snapshot с лимитами, а не бесконечный полный проект.
- Роутер инструментов зависит от качества ответа LLM, поэтому для важных функций есть прямые команды.
- У веб-интерфейса нет аутентификации — см. предупреждение в разделе
  [«Веб-интерфейс»](#веб-интерфейс).

# Работа Telegram-бота на Linux VPS

Это подготовка к переносу, не подтверждение действующего развёртывания.
Служба рассчитана на отдельный Linux VPS с systemd, Node.js в `/usr/bin/node`
и постоянным каталогом `/opt/ai-agent-artik`. Используй поддерживаемую LTS-версию Node.js,
совместимую с зависимостями проекта (для подготовки выбран Node.js 24).

## Что переносить

Переноси текущую рабочую копию, а не только HEAD: в ней есть незакоммиченные исправления.
Код: `index.js`, `package.json`, `package-lock.json`, `config.yaml`, `src/`, `docs/`,
`deploy/`, `README.md`. Не переноси Windows `node_modules/`: установи зависимости на сервере
через `npm ci --omit=dev` из каталога проекта.

Файл `/справка` для Linux уже скопирован в `docs/telegram-excel-guide.txt`.
После переноса изменения оригинала на домашнем ПК не синхронизируются автоматически.
Параметры окружения и пользовательские команды описаны в основном README.

Отдельно, через защищённое SSH-соединение, перенеси `.env` и данные:
`data/`, `exports/`, `backups/` (если существует), `memory.json` (если существует).
Сохрани структуру каталогов и имена файлов: память чатов содержит относительные пути к загрузкам.
Не публикуй архив с `.env` и данными в GitHub.
При настроенной PostgreSQL используется та же база; без неё нужен файловый `memory.json`.
Каталоги с данными должны сохраняться при обновлении кода.

## Служба

Создай системного пользователя `ai-agent` и каталог `/opt/ai-agent-artik`.
Пользователь службы должен иметь доступ к коду и право записи в рабочий каталог:
бот сохраняет память, загрузки, логи и результаты операций.
Файл `.env` должен принадлежать этому пользователю и иметь права `600`.
Приложение читает `.env` через dotenv из рабочего каталога; unit не копирует секреты.

После переноса файлов и установки зависимостей установи unit:

```sh
sudo install -m 644 deploy/ai-agent-artik.service /etc/systemd/system/ai-agent-artik.service
sudo systemctl daemon-reload
```

Перед первым запуском останови локальный polling этого же бота вместе с его
автоперезапуском в PM2. Финальную копию пользовательских файлов делай после остановки,
чтобы не потерять загрузки, пришедшие во время переноса.
Один токен должен обслуживаться только одним polling-процессом.

```sh
sudo systemctl enable --now ai-agent-artik
sudo systemctl status ai-agent-artik --no-pager
sudo journalctl -u ai-agent-artik -n 80 --no-pager
```

## Проверка после переноса

Проверь процесс службы, отсутствие `409 Conflict` в логах, ответ на `/stats`, `/db`
и `/справка`, загрузку Excel и получение результата. Строка «bot started» сама по себе
не подтверждает успешный polling. Убедись, что служба включена на автозапуск и после
перезапуска службы бот снова отвечает. Затем проверь ответ при отключённом домашнем ПК.

## Доступ к веб-интерфейсу через домен

Для VPS создай у регистратора DNS-запись `A`: имя `@`, значение — публичный
IPv4 сервера. Открой входящие порты `80` и `443` в firewall VPS/провайдера.
После обновления DNS установи Nginx и Certbot, затем включи подготовленный
reverse proxy:

```sh
sudo apt update
sudo apt install -y nginx certbot python3-certbot-nginx
sudo install -m 644 deploy/zoriopad.com.nginx.conf /etc/nginx/sites-available/ai-agent-artik
sudo ln -s /etc/nginx/sites-available/ai-agent-artik /etc/nginx/sites-enabled/ai-agent-artik
sudo nginx -t
sudo systemctl reload nginx
sudo certbot --nginx -d zoriopad.com --redirect
```

В `.env` на сервере задай `WEB_APP_URL=https://zoriopad.com`,
`WEB_APP_USERNAME=artik` и свой `WEB_APP_PASSWORD`, затем перезапусти сервис.
Production-веб-интерфейс без пароля закрыт; `/health` остаётся доступен
проверке сервера. В конфигурации Nginx проксируй запросы на
`http://127.0.0.1:10000`.

Для возврата на ПК сначала останови службу сервера:

```sh
sudo systemctl disable --now ai-agent-artik
```

Если на сервере появились новые загрузки или файловая память, скопируй их обратно
перед запуском локального экземпляра.
